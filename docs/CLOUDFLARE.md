# מעבר לשרת החדש בקלאודפלייר

המדריך מעביר את החלק המהיר של השרת לקלאודפלייר. הגיליון, ההגדרות, היומן והמייל נשארים בגוגל.
עד הצעד האחרון, אף ילד לא עובר לשרת החדש. רק הטלפון שבודק עובר.

כל ההגדרות נעשות דרך הדפדפן, רצוי במחשב. שמות הכפתורים באנגלית מופיעים בשורות נפרדות.

## צעד 1: חשבון חינמי בקלאודפלייר

1. נכנסים לכתובת:
   ```
   https://dash.cloudflare.com/sign-up
   ```
2. נרשמים עם מייל וסיסמה. לא צריך כרטיס אשראי.

## צעד 2: מאגר הנתונים

1. בתפריט בצד:
   ```
   Storage & Databases → D1 SQL Database → Create
   ```
2. שם המאגר:
   ```
   reading
   ```
3. יוצרים. אין צורך להגדיר טבלאות, השרת יוצר אותן בעצמו בפעם הראשונה.

## צעד 3: השרת

1. בתפריט בצד:
   ```
   Workers & Pages → Create → Create Worker
   ```
2. שם:
   ```
   aline-reading
   ```
3. לוחצים על הכפתור שמפרסם את השרת לדוגמה:
   ```
   Deploy
   ```
4. נכנסים לעריכת הקוד:
   ```
   Edit code
   ```
5. מוחקים את כל הקוד שבעורך, ומדביקים במקומו את כל התוכן של הקובץ:
   ```
   worker/dist/worker.js
   ```
   (ב־GitHub: פותחים את הקובץ, לוחצים על הכפתור
   ```
   Raw
   ```
   מסמנים הכול ומעתיקים.)
6. מפרסמים:
   ```
   Deploy
   ```

## צעד 4: חיבור המאגר לשרת

1. בעמוד של השרת:
   ```
   Settings → Bindings → Add → D1 database
   ```
2. שם המשתנה, בדיוק כך:
   ```
   DB
   ```
3. בוחרים את המאגר `reading` ושומרים.

## צעד 5: הסוד המשותף לגוגל סקריפט

הסוד הזה מאפשר לשרת החדש לקרוא את ההגדרות ולכתוב לגיליון, ומונע מכל אחד אחר לעשות זאת.

1. בגוגל סקריפט, יוצרים קובץ חדש בשם `Bridge` ומדביקים בו את התוכן של:
   ```
   server/Bridge.gs
   ```
2. מעדכנים גם את הקבצים:
   ```
   Util.gs, Router.gs, Logging.gs, Mailer.gs
   ```
3. בוחרים בראש העורך את הפעולה `makeBridgeSecret` ולוחצים "הרצה".
4. ביומן ההרצה מופיעה שורה עם הסוד. מעתיקים אותו.
5. מפרסמים גרסה חדשה של הסקריפט:
   ```
   Deploy → Manage deployments → ✏️ → Version: New version → Deploy
   ```

## צעד 6: מפתחות והגדרות בשרת החדש

בעמוד של השרת בקלאודפלייר:
```
Settings → Variables and Secrets → Add
```

כסוד (סוג `Secret`):

| שם | ערך |
|---|---|
| `GEMINI_API_KEY` | אותו מפתח שנמצא היום בהגדרות הסקריפט |
| `AZURE_SPEECH_KEY` | אותו מפתח של מיקרוסופט |
| `BRIDGE_SECRET` | הסוד מצעד 5 |

כטקסט (סוג `Text`):

| שם | ערך |
|---|---|
| `AZURE_SPEECH_REGION` | `uaenorth` |
| `BRIDGE_URL` | כתובת הסקריפט, זו שמסתיימת ב־`exec` |
| `ALLOWED_ORIGIN` | `https://michael-shalamaev.github.io` |

שומרים ומפרסמים.

## צעד 7: משימה קבועה

שורות ומיילים שגוגל לא קיבל ברגע הראשון נשלחים שוב כל כמה דקות.

```
Settings → Trigger Events → Add → Cron Triggers
```
ערך:
```
*/5 * * * *
```

## צעד 8: בדיקה שהשרת חי

1. בעמוד של השרת מופיעה הכתובת שלו, בצורה:
   ```
   https://aline-reading.<השם שלך>.workers.dev
   ```
2. פותחים אותה בדפדפן. צריך להופיע טקסט שמתחיל ב־`{"ok":true` ובו מספר גרסה שמתחיל ב־2.
3. שולחים לי את הכתובת. אני מכניס אותה לדף בבקשת מיזוג.

## צעד 9: בדיקה על "אבא"

אחרי שבקשת המיזוג אושרה:

1. פותחים בטלפון שלך את הקישור של "אבא" ומוסיפים בסופו:
   ```
   &server=new
   ```
2. בתחתית המסך צריך להופיע מספר גרסת שרת שמתחיל ב־2. הטלפון זוכר את הבחירה.
3. קוראים סיפור שלם. בודקים שהשורות מופיעות בגיליון ושהמייל הגיע.
4. כדי לחזור לשרת הישן, מוסיפים לקישור:
   ```
   &server=old
   ```

## צעד 10: המעבר של כולם

רק אחרי שהבדיקה עברה: אני משנה בבקשת מיזוג את ברירת המחדל לשרת החדש. כדאי שהמעבר ייכנס בלילה,
כי סיפור שהתחיל היום בשרת הישן לא עובר לשרת החדש.

**חזרה אחורה:** אותה שורה, בחזרה ל־`old`. הסקריפט הישן ממשיך לעבוד כל הזמן.
